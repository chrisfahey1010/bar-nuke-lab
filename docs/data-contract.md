# BAR Nuke Lab data contract

The Google Sheet is the editable source of truth. This application only issues public CSV GET requests. No credentials, external writes, sharing changes, replay access or execution.

## Exact header mapping

| Literal source header         | Meaning                                                                                   |
| ----------------------------- | ----------------------------------------------------------------------------------------- |
| Game ID                       | Literal match grouping identifier                                                         |
| Team ID                       | Match-local 1/2; blank unknown, never row-order inference                                 |
| OS                            | Numeric OS; -1 Unranked, distinct from 0                                                  |
| Position                      | Allowlisted role display mapping; raw preserved                                           |
| AN built time                 | Observed construction completion, elapsed time                                            |
| AN Type                       | AN category; absent does not prevent modeling                                             |
| Other positions covered       | Explicit role-level coverage, not map geometry                                            |
| Front situation upon AN build | Optional front context                                                                    |
| Nuke built                    | Observed silo completion                                                                  |
| First Nuke ready              | Observed first nuclear ammunition                                                         |
| First Nuke launch             | First recorded player launch; team minimum is only a candidate opening                    |
| Num nukes launched            | Legacy count, not inferred opening salvo size                                             |
| Positions targeted            | Opening target roles; raw token retained                                                  |
| Game duration                 | Once-per-game elapsed endpoint; unknown/conflicting entries use labeled 30:00 placeholder |
| Replay name                   | Once-per-game literal evidence reference; conflicting entries unavailable                 |
| Notes                         | Full original narrative, preserved verbatim                                               |

Required headers: `Game ID`, `OS`, `Position`, `AN built time`. Optional missing headers produce capability warnings, not total dataset rejection. Column order is irrelevant. Unknown columns and every nonempty row are preserved. HTML/login, malformed CSV, missing required headers and wholly unusable datasets are source failures: keep the last-good snapshot. Row-local invalid fields remain inspectable and are excluded only from calculations requiring those fields.

## Time and readiness

Accept exact elapsed `m:ss` or `h:mm:ss`, with seconds 00–59 and hour-form minutes 00–59. Blanks differ from invalid tokens (`?` is invalid). Never repair identifiers or malformed elapsed tokens. The strict parser treats `29:03:00` as 29 hours 3 minutes; unusually long durations trigger review. The user-confirmed exception is Game ID `7` with exact duration token `29:03:00`: its effective endpoint is corrected locally to `29:03`, without changing the raw token or parser. Any later valid source endpoint is respected. Display raw values alongside parsed/model values.

**Modeled AN readiness = observed AN construction completion + 90 seconds.** One named constant applies regardless of recognized, unknown, or missing AN type when completion is valid. The recognized display catalogue currently lists Citadel, Umbrella, Oasis; unknown names such as Prevailer/Haven remain available to filtering and calculations but have category warnings and generic markers. Assumes uninterrupted ammunition production; no manual interceptor-ammo entry required. Preserve completion/model provenance. Modeled readiness after match termination is outside the playable interval, not an in-game online event.

Blank completion means no owned AN before game end under the collection convention. Blank completion with a populated AN type is contradictory and unknown, not a negative observation. Unknown endpoints use the explicitly user-approved 30:00 placeholder for time-specific calculations. This is an assumption, not a recorded observation endpoint. Invalid/conflicting endpoints also use the placeholder and retain their validation issues. Recorded, placeholder and corrected provenance remains visible and exportable.

## OS relationship trendlines

The existing AN-time X / OS Y scatterplot uses **each row's own AN completion/readiness and that builder's OS**, never earliest allied target coverage or a provider's OS transferred to a recipient. Nonbuilders receiving coverage are not timing points. It supports per-position **quadratic least-squares fits**, `OS = a + b*t + c*t²`, where `t` is the plotted time in minutes. This is a descriptive fit of OS against time, not a model predicting completion time from OS. Fitting consumes the same valid own-builder milestones as the plotted points, after cohort filters and linked selection. Exclude unknown OS and Unranked; retain numeric OS 0 and repeated observations with equal per-row weight. The current timing basis and match-end eligibility remain authoritative.

A fit requires at least three distinct times and a numerically usable quadratic design. No fallback linear/cubic curve is manufactured for insufficient data. Exactly three ranked builders produce a dotted curve with an explicit interpolation/small-sample warning. Centering/scaling time and reorthogonalized QR avoid raw-time normal-equation instability. R² is descriptive and unavailable for constant OS, not an uncertainty or prediction guarantee.

Sample curves only between each position's observed time extremes. The 12:00–25:00 viewport never excludes fitting inputs. Negative fitted OS values are omitted from drawing rather than interpreted as Unranked. OS limits derive from cohort observations, not fitted extremes or layer visibility. Point/trendline toggles and position legend visibility are display-only; they do not change filters, denominators or exports. Fitted samples have no source-row references and never become linked selections. Source-record interactions take priority when points are visible; curve-only hover is clearly labeled fitted.

Position visibility is explicit shared page-session state, independent of layer flags. Both views use keyboard-accessible color-key buttons outside the plot; changing a layer, timing basis, filter, or tab must not restore a hidden position. Plotting combines position visibility with each independent point/curve flag. Reload restores both layers and all positions.

## Builder OS and recorded additional coverage

The **OS & neighboring coverage** panel sits under the compact OS relationship panel. `analyzeBuilderCoverage` in `src/analytics/builderCoverage.ts` consumes filtered/linked rows and full-context effective endpoints. Its denominator is usable **own timed builders**, with valid completion at or before the effective endpoint, a supported position, usable OS and interpretable coverage lists. It is independent of the clock, ongoing full-roster opt-in and observed/modeled display basis: valid completion at game end remains a placement observation even if modeled readiness falls after the endpoint. There is no 25:00 completion cutoff. Partial/review histories remain descriptive and are disclosed.

Count unique supported roles in `Other positions covered`, excluding the builder's own role; duplicate entries count once. A blank cell is **0 additional positions recorded**, not a confirmed coverage miss. A missing coverage column or a list containing unrecognized roles is excluded, not converted to zero or partially counted. Invalid/contradictory/after-end build timings, nonbuilders, unsupported builder roles and unknown OS are separately excluded. These exclusions are disjoint and reconcile with the input rows. Unknown teams can remain because the panel counts that builder's explicit claims rather than matching recipients. No geometry, physical adjacency, whole-team reach or recipient presence is inferred from the recorded role list.

Ranked OS bands are half-open ten-point intervals `[0,10)`, `[10,20)`, etc.; decimal OS and numeric 0 are retained. Unranked is a separate band. A horizontal 100% stacked bar shows the within-band shares with **0, 1, and 2+** additional positions recorded. Hover/table report counts, denominators, distinct games, and the **1+ recorded** share. Empty bands are not represented as zero. Bars are reference-free aggregates; the disclosure exposes inspectable builder records. Shared Role/OS/front/type/game/roster filters and linked selection apply to builders, not recipients.

These are sample proportions conditional on building, not predictions of whether any player builds an AN, proof of optimal placement, or causal OS effects. All-role bands mix positions; use Role to compare like positions. Same-game dependence, unidentified repeat players, team strategy and incomplete recording remain limitations. Small bands retain counts and descriptive shares without fitted probability curves or confidence claims. No extra collection fields or Sheet changes are required.

## Front situation at own AN completion

`Front situation upon AN build` is an optional snapshot of the builder's team at **that row's owned AN construction completion**, not a continuous match covariate. `analyzeFrontSituation` in `src/analytics/frontSituation.ts` accepts Disadvantage, Equal and Advantage after trimming/case-insensitive category matching; raw text remains unchanged. Populated unrecognized labels and missing labels are reported separately. Do not infer a front state for a nonbuilder or copy a provider's state onto allied coverage targets.

The front panel consumes the shared filtered/linked target rows but uses full-context game endpoints/roster provenance. Each point requires usable, interpretable owned completion and a recognized front label. Permanent cohort cutoff is completion **<=1500 seconds (25:00)**; there is no later-completion opt-in. Earlier completions are retained. The cutoff is completion-based in both timing modes. Observed mode plots completion; modeled mode plots completion + the named delay, excluding readiness after the effective endpoint. Its fixed **12:00–25:00** view crops off-screen points without removing them from summaries. Desktop uses the same left-column width and shared horizontal plot gutters as the readiness panel; builder OS/additional coverage occupies the second-row right column. Existing invalid/after-end/type-contradiction rules apply. Exclusions are disjoint and reconcile with input rows; front-without-valid-time is a separate diagnostic count, not another exclusion category.

The shared **Front situation** selector appears before AN type, defaults to All situations (`Filters.front = ''`), and accepts Advantage, Equal or Disadvantage. `selectRows` uses the same `parseFrontSituation` normalization as the panel, matching the target row's raw completion label rather than a provider's label. Missing and unrecognized labels match All situations only. This target filter applies to shared charts/cards/selection/table/export cohorts, never to context construction or provider lookup. Selected readiness percentages describe labeled observations and do not estimate all-player coverage conditional on a continuously measured front state; the denominator caption and Methodology make that restriction explicit.

Group by position and front category. Each event has equal descriptive weight; report builder count and distinct games because same-match rows are related. Quartiles/median use linear interpolation at `(n-1)*p`. Show summary ticks/IQR/table medians only with >=5 builders and >=3 distinct games. Equal-baseline difference is the group median minus its own position's Equal median, only when both meet that threshold. Sparse groups expose real points and counts, not promoted summaries. The threshold is an interface safeguard, not a significance test; IQR is not a confidence interval.

These are conditional builder-event associations, not front-specific population coverage probabilities, causal effects, deadline recommendations or earliest-allied-coverage analysis. Front at completion and build time can influence each other; role stratification/OS filtering does not remove selection bias or confounding. Descriptive partial/review history remains eligible independently of the ongoing-game full-roster denominator, Game Clock and partial opt-in. The completion cutoff is an explicit cohort filter, unlike the display-only time window on the existing readiness/OS charts. Source/export data are not removed by this panel's cutoff. No extra nonbuilder or endgame front recording is required.

## Games and coverage

16 usable player rows infer a full 8v8 roster; fewer are partial. Overcounts, duplicate-looking rows, unexpected role repetition and contradictory identity values trigger review, never deduplication. An explicit 8/8 split strengthens inference; unknown teams stay unknown. Repeated metadata aggregates only if it agrees. No spreadsheet propagation.

Compute games/metadata/coverage from the full validated dataset BEFORE target filters. A provider covers its own role and explicitly recorded additional roles, using the earliest modeled-ready provider within the same known game/team. `Other positions covered` splits comma/semicolon-separated roles, normalizes supported display names, and preserves the raw cell; `Sea beach, Front2` means two roles, not one combined label. Own readiness survives unknown Team ID. Cross-row allied matching requires known teams. Duplicate target-role candidates are exposed. Empty provider evidence means “No recorded coverage yet”, not guaranteed vulnerability.

## Denominators and opening episode

The Game Clock UI spans 720–1500 seconds (12:00–25:00), defaults to 900 seconds (15:00), and moves in one-second steps. This matches the timing charts' visible time window; it does not remove source observations outside the window. The Modeled Timing Window retains the selected-clock marker but has no hypothesis label or shaded time interval. The descriptive observed/model toggle changes OS charts and role milestones, not the modeled basis of ongoing percentage summaries or readiness curves.

Default ongoing-game percentages use inferred-full, non-review games with effective duration strictly greater than selected time. Cohort filters then select interpretable player observations; equal-to-ready counts online. Display numerator/N, distinct games, exclusions and unknowns. N=0 is unavailable, not 0%. Partial games require opt-in and are labeled selected observed-player samples. Slots are not verified survivors/intact bases. Timed-builder distributions use only valid timed AN builders and remain useful without duration.

The Modeled Timing Window plots **AN readiness (%)** on a fixed 0–100% Y axis. With the explicit **All roles** filter, it shows only recorded target coverage, stratified into one step curve per retained target position using the same position colors as OS relationship. Each position has its own eligible coverage denominator at every whole second; these are not the pooled all-role percentage card. A linked selection containing only one position does not change the All roles display mode. With an individual role filter, both original curves remain: own modeled AN online / own interpretable N and recorded target coverage / coverage interpretable N, agreeing with the cards. All curves use the same ongoing summary calculation, target filters, linked selection and partial-roster opt-in, with providers and roster status retained from full context. Readiness before 12:00 contributes to the initial percentage; later milestones are not removed from the source data. Each game leaves both numerator and denominator at its effective endpoint, including games that ended without coverage. The changing cohort can make percentages increase or decrease. Unknowns remain excluded; unavailable percentages are null gaps, not zero or a carried-forward result. These are aggregate curves, not selectable source-row milestones; source inspection remains on OS points and tables. Hover exposes position/time, percentage, numerator/N and ongoing game count rather than a fixed all-history sample size. The external position key keeps the plot independent of dense native legends.

Opening shot/salvo may have multiple missiles/targets. Preserve source first-launch entries and notes; earliest teammate launch is a candidate opening episode, not confirmation of complete collection. Do not interpret legacy total count as salvo size or manufacture additional missile timestamps. Launch is not impact; a launch-time coverage snapshot proves neither hit nor interception. No later nuclear campaigns, hit-success prediction, depletion or survival/causal model.

Exports retain raw fields, source row reference, retrieval/import provenance, model delay, clearly named observed/modeled seconds, coverage provider references, roster/team state and metadata availability. Effective and strictly parsed source endpoints are separate: `derived_game_duration_seconds`, `derived_recorded_duration_seconds`, `derived_duration_source` (recorded/placeholder/corrected), and `derived_duration_note`. The chart time window (12:00–25:00) affects display only; early/late records remain in summaries and exports. JSON separates raw/derived namespaces and retains extra-cell row errors in its CSV roundtrip. CSV uses the full field union; a generated name colliding with a literal source header is repeatedly prefixed with `lab_`, never allowed to overwrite the raw value. Filtered exports do not claim a full roster from exported row count; re-import a full dataset to recover complete context.
